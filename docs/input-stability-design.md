# 输入稳定性与迟到手势防误触设计

日期：2026-10-14。基线提交：`c5376a0`。
状态：2026-10-14 已实施，revision 12。用户距离、角度与补偿窗口保留；实际手势待用户验收。

> 2026-10-17 更新（revision 13–16）：本文的“迟到移动补偿”（松开后 120 ms 观察窗）已移除。探针实测 Deskflow 下的根因是 Windows 端鼠标手势软件（StrokesPlus.net）扣住右键按下，松开后才补发，手势移动以普通移动先于按下到达。现改为 `PrePressGesture` 向按下前回溯，且只用于补发笔画：按下到松开不超过 50 ms（无拖动点击不超过 10 ms）。真实按住的右键只按按住期间的拖动判定。Windows 端已在光标切到 Mac 时自动禁用该软件。下文其余的取消编号、线程隔离、故障处理设计仍然有效。

## 目标与证据边界

用户确认迟到移动补偿后，Deskflow 短上滑复制和短下滑粘贴已改善。保留当前 8 pt 常规阈值、3 pt 短上滑、短下滑规则、方向角度和 120 ms 补偿窗，不继续通过缩小阈值优化。

此前系统点击/拖动失效，在 Deskflow 保持运行、退出 MouseGesture 后恢复；同时存在监听被系统禁用后反复启用的日志。可确认工具与故障相关，但尚未证明是哪段内部逻辑触发系统异常。已有保护遇到禁用即停止监听，下一版需完善状态反馈、取消机制与架构隔离。

## 一、监听和动作隔离

事件监听使用专用线程及 CFRunLoop；回调只读取事件坐标、类型、时间和来源，更新手势状态，决定拦截或放行，提交不可变动作请求。禁止在回调内查询 AX、访问剪贴板、投递合成事件、读取文件、等待 Task 或跨线程同步等待。日志聚合后异步输出。

当前 MainActor 上的窗口查询、窗口切换和快捷键任务与回调分离。主线程维护最近的前台应用快照；回调读取快照，不同步等待主线程。快照有效性在执行前重新验证，不能把过期快照当作执行许可。所有 AX 查询放在后台执行，设置超时并限制并发；结果携带手势编号。实际 AppKit 操作在主线程执行，单个手势最多投递一次动作。

监听状态只有一个线程负责修改，动作取消编号用短小线程安全访问实现；不持锁调用系统 API。主线程忙时不应阻塞监听线程。投递点击和快捷键的执行队列同样不能反向等待监听线程。

## 二、统一手势状态机

| 状态 | 进入条件 | 允许行为 | 结束条件 |
| --- | --- | --- | --- |
| Idle | 没有手势 | 原样放行普通输入 | 右键按下 |
| Tracking | 右键按下 | 记录按住期间轨迹 | 松开、停用或监听异常 |
| PendingLateMotion | 未识别且符合补偿条件的松开 | 收集最多 120 ms 的迟到移动 | 识别完成、到期或新输入 |
| ActionPending | 已识别上/下/右 | 验证目标并执行一次 | 执行、取消或超时 |
| Faulted | 系统禁用监听或监听内部异常 | 全部放行，清理状态 | 用户主动恢复 |

每次右键按下、新的鼠标按下、键盘按下、滚轮、前台应用切换、停用或故障，递增取消编号。轨迹、补偿定时器、后台 AX 查询、排队点击、排队动作均绑定编号；执行前再次检查。旧任务只能丢弃，不能影响新手势。

键盘只观察事件类型用于取消，不读取或保存键码、文本。取消事件本身必须原样放行。移动本身不触发取消，否则迟到补偿无效。

## 三、迟到移动的防误触规则

1. 继续只恢复上、下、右，不把迟到左移猜成置顶动作。不扩大 120 ms 窗口，也不推断零移动手势。
2. 使用单调时钟记录释放时刻及截止时刻；即使主线程定时器延迟，也不接纳截止后的移动。记录完成时间与事件送达时间，诊断延迟但不将时钟混用。
3. 至少两次迟到移动、符合当前距离及角度要求才能恢复。保持左右各 20° 的下滑范围和目前右滑边界。明显反向、来回抖动或主要横向峰值与短上下滑冲突时拒绝。
4. 只接纳未被本工具标记为合成的移动；进入补偿期间发生新输入或前台应用改变，取消补偿，不回放旧点击。
5. 补偿成功与普通右键回放互斥。到期无手势、目标未变化且无新输入时，只在原按下坐标回放一次点击；不在后来移动到的按钮上回放。
6. 新右键按下到来时，不能像当前逻辑一样无条件回放旧待定点击；取消旧任务，并开始新手势。

普通右键后立刻移动与真正迟到拖动可能产生相同事件序列，Mac 端不能百分之百区分。两次移动、方向一致、短观察窗与取消机制只能减少误触；不能宣称完全消除。先不另加更长延迟或更低距离。

## 四、复制粘贴目标验证

按下时保存有效原应用 PID、手势编号、可获得的窗口身份；PID 无效且没有可信前台快照时，不在松开后随意选一个应用。

已有窗口：执行前原应用仍在前台、焦点窗口身份一致才允许投递。缺窗口：只在同一个原应用内恢复窗口，需至少两次采样间隔 30 ms 确认稳定，总等待不超过现有 600 ms。窗口暂时不可读时保留等待，而不是立即判失败。AX 查询在后台，结果回到执行队列时重新检查取消编号和当前前台应用。

不自动点击控件、不激活或抬升其他窗口、不更改插入点、不通过读取/重写剪贴板来推断成功。新输入取消旧动作。最多发送一次快捷键，不做复制/粘贴重试；“已投递”不等同于目标应用已经执行。

## 五、故障保护与菜单栏状态

系统禁用监听时，不自动重启；清空 Tracking、补偿点击和所有待执行动作。发布 Faulted 状态给菜单栏，显示“手势已暂停：输入监听异常”，普通输入继续放行。

菜单栏明确显示正常、用户暂停、故障暂停、权限不足四种状态。故障恢复需用户点击“恢复手势监听”；权限不足则引导授权。恢复前重建监听并重置所有取消编号与轨迹。恢复再次失败时保持暂停，禁止重试循环。状态来源是实际监听状态，不仅是配置 enabled。

后续可加独立线程的监听存活检测；若实现，必须先验证检测不会把无鼠标活动误判为卡死，不依赖“最近一次输入时间”，且清理不能等待已经阻塞的主线程。首轮不自动加入未经验证的 watchdog。

## 六、验证与实施顺序

先实现状态机、取消编号和回归测试，再隔离监听/AX/动作线程，最后接菜单栏状态。保留本基线作为可回退版本，不同时改角度、距离或网络设置。

自动化验证至少覆盖：

- 迟到上/下/右正常恢复；零事件、单事件、抖动、反向以及过期事件不触发。
- 新点击、键盘输入、滚轮、切应用、停用或故障到来后，旧 AX 结果、定时器和动作均不能执行。
- 普通点击最多回放一次，补偿成功不回放；取消后不在新位置补点。
- 已捕获窗口不匹配必须取消；缺窗口仅同应用稳定后允许；PID 无效、应用退出不允许投递。
- 人工制造慢 AX 查询或主线程工作时，监听回调不能同步等待；故障通知后不自动重新启用。
- 参数和当前上/下/右分类回归不变；状态显示与实际监听一致。

这些验证使用纯状态机测试和可控测试替身，避免在用户正常工作时注入点击/快捷键或制造系统卡死。完成后只构建安装一次，实际 Deskflow 手势和普通右键由用户按正常习惯验收，不反复要求演示。


## 实施记录（revision 12）

- 新增专用 `InputRunLoop`，监听回调不调用 AX、AppKit 查询或事件投递；主线程繁忙时监听线程仍独立处理输入。
- 新增线程安全 `InputLifetime`，旧点击、补偿定时器、AX 结果和动作统一校验编号与原应用。每个编号只能认领一次动作；合成事件通过自身标记排除。
- 复制粘贴 AX 读取在独立串行队列、30 ms API 超时内执行；等待仍最多 600 ms，缺窗口稳定要求仍为 30 ms。系统窗口切换与置顶动作沿用主线程执行，但不会反向阻塞监听；没有新增自动窗口激活或复制粘贴重试。
- 补偿窗仍为 120 ms；新输入取消旧点击；普通点击回放在按下坐标，补偿成功不回放。新增迟到轨迹明显反向拒绝；正常按住轨迹的方向算法不改。
- 菜单栏显示正常、暂停、异常与权限不足，异常停止拦截，只允许用户主动恢复。
- 自动测试覆盖 22 项分类/恢复/取消/竞争验证，以及 2 项输入线程独立于主线程、启动期间任务顺序验证。测试未安装系统监听、未向用户应用注入操作，也未人为制造系统卡死。
- 参数文件没有改写；原有 8 pt、3 pt 短复制、20° 下滑以及 120 ms 补偿保持。原始系统输入异常的精确内部原因尚未证实，不能宣称这次会消除所有 macOS/Deskflow 输入故障。
